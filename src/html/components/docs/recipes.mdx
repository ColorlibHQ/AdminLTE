##### Highlighting the active sidebar item from JavaScript

If you're rendering the sidebar once and want client-side route highlighting:

```js
function setActiveSidebarItem(href) {
  document.querySelectorAll(".sidebar-menu .nav-link").forEach((el) => {
    el.classList.toggle("active", el.getAttribute("href") === href)
  })
}

// Call on route change
setActiveSidebarItem(window.location.pathname)
```

##### A language switcher wired to a real locale

The demo topbar ships a language dropdown, but the markup alone changes nothing — swapping the locale is the application's job, and doing it badly is worse than not shipping it. The pattern below covers what a switcher actually has to get right.

```html
<li class="nav-item dropdown">
  <a class="nav-link" href="#" id="language-menu" data-bs-toggle="dropdown"
     aria-expanded="false" aria-label="Change language, current language English">
    <i class="bi bi-translate" aria-hidden="true"></i>
  </a>
  <ul class="dropdown-menu dropdown-menu-end" aria-labelledby="language-menu">
    <li>
      <a class="dropdown-item active" href="/en/dashboard" hreflang="en" aria-current="true">
        English <i class="bi bi-check-lg ms-2" aria-hidden="true"></i>
      </a>
    </li>
    <li><a class="dropdown-item" href="/es/dashboard" hreflang="es">Español</a></li>
    <li><a class="dropdown-item" href="/ar/dashboard" hreflang="ar">العربية</a></li>
  </ul>
</li>
```

Four things make the difference between a working switcher and set dressing:

1. **Each item is a real link to the same page in another locale**, not a `#` with a click handler. A link is bookmarkable, crawlable, opens in a new tab, and works before your JavaScript loads. Add `hreflang` so assistive tech announces the language change and search engines can pair the URLs.
2. **The locale belongs in the URL** (`/es/dashboard`) or in a cookie the server reads — not in `localStorage`. Server-rendered HTML has to know the locale *before* it renders, and `localStorage` is only readable after the page has already been sent in the wrong language.
3. **Mark the current language** with both `.active` and `aria-current="true"`, and name it in the toggle's `aria-label`. A flag icon alone is not a language: several languages share a flag, and several countries share a language.
4. **Switching to an RTL locale needs the RTL stylesheet**, not just a `dir` attribute. Serve `adminlte.rtl.css` and set `<html lang="ar" dir="rtl">` together — see [RTL Support](rtl.html).

If your locale lives in the URL, the server picks the stylesheet and the switcher stays pure markup:

```html
<!-- Rendered per request from the active locale -->
<html lang="ar" dir="rtl">
  <link rel="stylesheet" href="/css/adminlte.rtl.css">
```

For a client-rendered app, do the same work at the router level — change the locale, re-render, and swap the stylesheet `href` — rather than translating text nodes in place.

##### Reacting to layout/sidebar changes

Listen for plugin events to coordinate with your own code — e.g., refit a chart when the sidebar collapses (so the chart re-measures its container width):

```js
let chart = /* your ApexCharts instance */

document.addEventListener("collapse.lte.push-menu", () => {
  // wait for the transition to finish (~300ms by default)
  setTimeout(() => chart.updateOptions({}), 350)
})

document.addEventListener("open.lte.push-menu", () => {
  setTimeout(() => chart.updateOptions({}), 350)
})
```

The same pattern works for Tabulator, FullCalendar, and any other library that reads its container width on init.

##### Loading content into a card via fetch

```html
<div class="card" id="users-card">
  <div class="card-header">
    <h3 class="card-title">Users</h3>
    <div class="card-tools">
      <span class="spinner-border spinner-border-sm text-secondary d-none" id="users-spinner" role="status"></span>
    </div>
  </div>
  <div class="card-body p-0">
    <div id="users-body" class="text-secondary p-3">Loading&hellip;</div>
  </div>
</div>

<script>
  const spinner = document.getElementById("users-spinner")
  const body = document.getElementById("users-body")

  spinner.classList.remove("d-none")
  fetch("/api/users")
    .then((r) => r.text())
    .then((html) => { body.innerHTML = html })
    .catch(() => { body.textContent = "Failed to load." })
    .finally(() => spinner.classList.add("d-none"))
</script>
```

##### Charts that follow dark mode

Charting libraries draw their own text and tooltips, so they know nothing about `data-bs-theme`. ApexCharts, for instance, renders a light tooltip and dark-grey axis labels by default — on a dark card the tooltip's inherited text colour is near-white on white and unreadable. The library has a dark theme; you just have to tell it which one to use, and update when the mode changes.

Every demo page ships this helper (it is part of the shared scripts at the bottom of the page). It sets ApexCharts' global default `theme.mode` from `<html data-bs-theme>` **before** any chart is created, keeps the chart background transparent (dark mode would otherwise paint it grey), and watches the attribute so every chart that has a `chart.id` follows the toggle, the OS preference in auto mode, or your own code:

```html
<script>
  const mode = () => (document.documentElement.getAttribute("data-bs-theme") === "dark" ? "dark" : "light")
  globalThis.Apex ||= {}                                   // ApexCharts' global options object
  Apex.theme = { mode: mode() }
  Apex.chart = Object.assign(Apex.chart || {}, { background: "transparent" })
  new MutationObserver(() => {
    const next = mode()
    Apex.theme = { mode: next }
    for (const { chart } of Apex._chartInstances || []) {
      chart.updateOptions({ theme: { mode: next } }, false, false)
    }
  }).observe(document.documentElement, { attributes: true, attributeFilter: ["data-bs-theme"] })
</script>
<script src="https://cdn.jsdelivr.net/npm/apexcharts@3.37.1/dist/apexcharts.min.js"></script>
```

Give each chart an `id` so it is registered for the live update:

```js
new ApexCharts(document.querySelector("#revenue-chart"), {
  chart: { id: "revenue-chart", type: "area", height: 300 },
  // …
}).render()
```

If you prefer the ColorMode event to the attribute observer, `document.addEventListener("changed.lte.color-mode", e => …)` receives `e.detail.resolved` (`"light"` or `"dark"`); the observer above additionally covers OS-preference changes in auto mode and any code that sets the attribute directly. The same idea applies to other libraries — Chart.js reads `Chart.defaults.color` / `Chart.defaults.borderColor`, which you can set from `getComputedStyle(document.body)` and re-apply with `chart.update()` in the same observer.

##### Printing a page as a document

AdminLTE prints the whole layout — sidebar, header and content — with the styles you would want for reading a copy of a screen: the target of an external link is printed after it, buttons keep an outline so they still read as buttons, and everything goes black on white so backgrounds don't eat ink.

For pages that print as *documents* — an invoice, quote, work order or packing slip that goes to a customer — that is the wrong output: nobody wants `Pay online (https://pay.example.com/inv/12345?token=…)` on a printed invoice, or a box drawn around a button. Put `data-lte-print="plain"` on `<html>`, `<body>` or any container and both go away, while the text stays black on white:

```html
<html lang="en" data-lte-print="plain">
```

Scope it to part of a page when only that part is the document:

```html
<div class="card" data-lte-print="plain">…the invoice…</div>
```

Hide the chrome for that print with Bootstrap's own utility — `.d-print-none` works on any element, including the sidebar and the header:

```html
<aside class="app-sidebar bg-body-secondary shadow d-print-none" data-bs-theme="dark">…</aside>
<nav class="app-header navbar navbar-expand bg-body d-print-none">…</nav>
```

And if a page only ever prints as a document, set the attribute once when you print:

```js
document.querySelector("#print-invoice").addEventListener("click", () => {
  document.documentElement.setAttribute("data-lte-print", "plain")
  window.print()
})
```
